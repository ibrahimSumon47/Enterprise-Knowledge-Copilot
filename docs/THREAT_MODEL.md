# Threat model

Scope: the web app on Vercel, the FastAPI service on Render, and the Supabase
project (Postgres, pgvector, Auth, RLS). The corpus is public handbook text plus
clearly labelled synthetic confidential documents; no real customer data exists
in this system.

## Assets

| Asset | Why it matters |
| --- | --- |
| Department and confidential passages | The whole point of the access model: a leak invalidates the product claim. |
| `profiles.role` / `profiles.department` | The authorisation input; the API reads it, the client never supplies it. |
| `SUPABASE_SERVICE_ROLE_KEY`, model API keys | Bypass RLS or spend the owner's quota. |
| Audit log | Evidence of who asked what; tampering hides misuse. |
| User sessions | A stolen token is a stolen role. |

## Trust boundaries

1. Browser → Vercel (untrusted input, no secrets beyond the anon key).
2. Vercel → FastAPI (bearer JWT, CORS allowlist).
3. FastAPI → Supabase (service role for writes, caller JWT for identity).
4. Retrieved text → prompt (untrusted data, never instructions).

## STRIDE

| Threat | Vector | Control | Where |
| --- | --- | --- | --- |
| Spoofing | Forged `role` in a request body | Identity comes from the verified JWT; the role is loaded from `profiles` | `api/app/auth.py` |
| Tampering | Editing or deleting audit rows | Hash chain verified on demand | `api/app/audit.py`, `/audit/verify` |
| Repudiation | "I never asked that" | Every question, refusal and document id is recorded with actor and role | `api/app/audit.py` |
| Information disclosure | Retrieval returning another department's passage | Access predicate inside `search_chunks`; RLS on the tables | `supabase/migrations/20261111000100_init.sql` |
| Denial of service | Flooding `/chat` | Per-user sliding-window rate limit in Postgres | `api/app/db.py` |
| Elevation of privilege | Calling admin routes with an employee token | `require_admin` re-checks the stored role, never the claim | `api/app/auth.py` |
| Prompt injection | A retrieved passage says "ignore previous instructions" | Retrieved text is labelled as data, answers are verified against cited chunks, injection probes are in the golden set | `api/app/pipeline.py`, `eval/golden_set.jsonl` |

## OWASP LLM Top 10 (2025)

| Risk | Status in this project |
| --- | --- |
| LLM01 prompt injection | System prompt treats sources as data; citation verification rejects uncited claims; injection questions are evaluated. Residual: a clever injection can still change tone, not access. |
| LLM02 sensitive information disclosure | Access is enforced before generation; service-role keys never reach the browser; logs redact emails and bearer tokens. |
| LLM03 supply chain | Pinned dependencies, `pnpm audit` and `pip-audit` in CI, CodeQL, secret scan over full history, SHA-pinned actions. |
| LLM04 data and model poisoning | Corpus is a pinned slice with a hash per document; synthetic documents are generated by a committed script. |
| LLM05 improper output handling | Answers are rendered as text, never as HTML; no tool calls are executed from model output. |
| LLM06 excessive agency | The pipeline can retrieve, answer and refuse. It cannot write to documents, change roles or send anything. |
| LLM07 system prompt leakage | The prompt refuses to reveal itself; it contains no secrets. |
| LLM08 vector weaknesses | Embeddings are access-filtered at query time; cross-role probes must return zero passages. |
| LLM09 misinformation | Refusal below the rerank threshold; answers must cite; a low-overlap answer fails verification. |
| LLM10 unbounded consumption | Question length cap, candidate cap, rate limit, token ceiling per answer. |

## Residual risks (honest list)

1. **Free-host memory.** The 512 MB instance cannot hold the multilingual
   encoder and the cross-encoder together; heavy requests can restart it. The
   service degrades to hybrid retrieval instead of failing, but availability is
   best-effort.
2. **Demo credentials.** Seven role accounts share one password held outside the
   repository. They are demo identities; rotate or delete them before any real
   deployment.
3. **No WAF or CDN-level bot defence.** Rate limiting is per account, applied in
   Postgres; a distributed anonymous flood is out of scope for the free tier.
4. **Single-region data.** Supabase `ap-south-1` plus Render `singapore`; no
   multi-region failover.
5. **No independent penetration test.** Controls are tested by the repository's
   own suite, not by a third party.

## Shared admin account

The admin account is shared with reviewers, which turns two ordinary admin powers
into threats: destructive edits and silent permission changes. Controls: document
deletion is refused (403, audited), access-level edits are audited and reset
nightly, and both behaviours have tests in `api/tests/test_units.py`.
